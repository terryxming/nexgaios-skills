# 私有工程纪律：skill 生产

本文件是[通用工程纪律](engineering-discipline-universal.zh.md)在**本仓库（skill 生产流水线）**这个具体领域的落地。通用纪律讲"怎么写好代码",本文件讲"这些原则在造 skill 时具体长什么样",并补充 skill 特有的、通用纪律没覆盖的规则。

两层同时生效。冲突时,以更严格的一方为准。

---

## A. 通用纪律 → skill 场景的映射

| 通用纪律 | 在本仓库的具体形态 |
|---|---|
| ① 写之前先读 | 新建 skill 前先读 `templates/` 和已有同类 skill；改 skill 前先读它的 `SKILL.md`、`evals/` 和 changelog。 |
| ② 编码之前先思考 | 动手前先说清:这个 skill 的触发边界是什么(何时该触发、何时**不**该)、目标平台差异、是否真需要新建而非扩展已有。 |
| ③ 简单性 | 一个 skill 只解决一类任务。`SKILL.md` 正文优先短小,细节拆到 `references/` 按需加载,不要一上来就上多文件脚手架。没有第二个用例前不做抽象。 |
| ④ 外科手术式修改 | 一次改动只动一个 skill 目录;不顺手重排 frontmatter、不重格式化他人 skill。`dist/` 是构建产物,**永不手改**。 |
| ⑤ 验证 | 改 `SKILL.md` 前,先把要修的问题写成 eval 用例,先跑、看它挂,改完再跑、看它过。见 §C。 |
| ⑥ 目标驱动 | "做个 X skill"要先具体化为可验证标准:触发正/负例各几条、执行场景的验收 rubric 是什么。 |
| ⑦ 调试 | skill 不触发/误触发时,先复现(用 eval 用例),再定位是 `description` 问题还是正文问题,一次只改一处。 |
| ⑧ 依赖 | skill 的 `scripts/` 能用标准库就不引三方包;`compatibility` 字段如实声明环境依赖,不隐瞒。 |
| ⑨ 沟通 | 平台兼容性等难逆转的决策,写进 `docs/decisions/` 并**附证据来源**,不做隐形决策。 |
| ⑩ 常见失败模式 | 尤其警惕"知识幻觉":涉及 Codex 等非 Claude 平台的机制,先查官方文档再落笔,存疑项标注待实机验证。 |

## B. skill 特有硬约束（能脚本化的进 lint/CI，不靠自觉）

原则:**凡机器可校验的纪律,一律做成门禁,绝不留在文档里靠人/agent 自觉。**

1. **规范合规**(集成官方 `skills-ref validate` + 自建检查):
   - `name`:≤64 字符,仅小写字母/数字/连字符,不以连字符起止,无连续连字符,且**必须等于父目录名**。
   - `description`:≤1024 字符,非空,且必须同时写清"做什么"和"何时用/何时不用"。
   - `SKILL.md` 正文建议 <500 行;超限应拆分到 `references/`。
2. **单一事实源一致性**:`dist/` 必须能由 `skills/` 经构建脚本完整重生;CI 校验 `dist/` 无手工漂移。
3. **平台可移植**:skill 源不得写死机器路径或平台特有假设;平台差异(Codex 的 `agents/openai.yaml` 等 sidecar)与 SKILL.md 分离,不污染规范。
4. **中文化**:产出物(含 `description`、正文、changelog)一律中文。工作语言为中文。

---

## C. 评测即回归（迭代闭环）

1. **两层评测,用例随 skill 走,runner 共享**:
   - **触发评测**:一批正例/负例 prompt,验证 `description` 该触发时触发、不该触发时不触发(skill 最常翻车处)。
   - **执行评测**:场景 + 验收 rubric,验证触发后任务完成质量。
2. **失败即用例**:线上遇到的每个失败案例,回填成一条 eval 用例,再改源码。改完跑全量回归,通过才允许 re-release。
3. 用例入库(`skills/<name>/evals/`),运行产物不入库(见 `.gitignore`)。

---

## D. 发布门禁（release gate）

一个 skill 允许发布/更新,必须依次通过:

1. `skills-ref validate` + 自建 lint 全绿;
2. 该 skill 的触发评测与执行评测达标;
3. 版本按 skill 独立 bump(记录在 `metadata.version`),生成/更新 changelog;
4. 构建到 `dist/`,校验与源一致;
5. 变更涉及难逆转决策的,`docs/decisions/` 有对应记录。

任一不过,不予发布。

---

## E. 跨设备协作纪律

1. **状态进仓库,不进对话/本机记忆**:任何需要在另一台机器接续的信息,必须落到仓库文件并 push。git 是唯一同步通道。
2. 收工 `/handoff`:生成交接文档(进度、已定决策、下一步、未决问题)入 `journal/`,commit + push。
3. 续工 `/resume`:先 pull,读最新交接文档与 `docs/decisions/`,再动手。
4. 决策留痕:难逆转的选择进 `docs/decisions/`,避免另一台机器上重复调研或凭记忆瞎猜。
