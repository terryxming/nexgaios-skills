# 0011. 问答为基底,信号/噪音分离为核心引擎(ob-notes 架构翻转)

- 状态:已接受(整套架构未经 dogfood 实测,试行待验证——见存疑段)
- 日期:2026-07-04
- 决策人:terry(公司机)+ Claude

## 背景

ob-notes v1.0.0 候选当前是**分类驱动**:先把这次沉淀判定成研究型 / 实战型 / 问答实录型三选一,再套对应的固定模板。审查这一步的必要性,结论要分两层:

- **要不要区分不同结构的笔记?** 要。三个模板的骨架(论述结构 / 问题-解法结构 / 追问序列结构)与专属取舍纪律(source-fidelity、mastery-lens、问题保真)是真实不同的,不是换个 tag。这是本 skill 钉死"格式飘 / 没重点"的核心价值。
- **要不要用"先分类三选一 → 套固定模板"这个形式实现区分?** 这里有三处张力:①三类**非 MECE**、交叉是常态(SKILL.md 自己用"选主类型 + 双链回指"打补丁);②固定模板有**诱导填空**副作用(mastery-lens 自警不能做成"## 复述 / ## 迁移"章节,否则表演式伪掌握);③三份"该记什么 / 该丢什么"高度重复,SSOT 压力。

更根本的洞察:**几乎所有有长期价值的知识都产生于问答**。哪怕"研究一个概念",也是用户与 agent 一问一答逼出来的;用户的"问"不是要压缩掉的过程噪音,而是**认知路径的坐标**——记录了困惑如何被一步步想通,丢掉它就背离了"沉淀有价值信息"的初衷。所以问答不是三类之一,而是**基底**。

进一步:**"有没有问"是"消化与否"的判据**。啃一篇外部长文若用户对它没有任何疑问,说明并未消化吸收、只是顺手存档——那不该由一个"沉淀消化后知识"的 skill 来精加工。于是"外部材料"从来不是独立分支:伴随问则回到问答基底,无问则根本不该进来。

## 决策

1. **核心重定位**:ob-notes = 从问答里,把**已消化**的知识分离出来,按复用目标呈现,写回 Obsidian。
2. **问答为唯一基底,无例外**。外部材料吸收:伴随问 → 回基底;**无问的顺手存档划出本 skill**(交给剪藏 / 稍后读工具,如 Obsidian Web Clipper),ob-notes 只做消化后的知识——消化才是它的护城河,存档没有。
3. **workflow 翻转:分离先于分类。** 信号/噪音分离提为第一动作,呈现侧重退居其后。新序:触发 → preflight 校验落点(铁律一)→ **信号/噪音分离** → 定呈现侧重 → 套呈现骨架 + frontmatter/可信度/日期(铁律三、四)→ 写盘前质量自检。
4. **信号/噪音分离引擎(新核心),三条定义:**
   - **① 单一判据 + 三限定参照读者**:「删掉这条,一个**没有这场对话记忆、不熟这个主题、但懂通用常识**的人,理解会不会受损?」受损 = 信号,留;不受损 = 噪音,滤。前两限定实现"防误删"(笔记的作用是对抗遗忘,三个月后关于此主题的记忆 = 这篇笔记),第三限定给下界、挡住"记常识"式过度保留。
   - **② 问题保真、回答重写升为基底通则**:信号里唯一**原样保真、不许改写**的是用户的问(它是认知坐标、是史料);其余信号一律**重写成给未来读者的讲解**。重写锁死在叙述组织层,四条镣铐:(a) 只重组不新增——不引入对话里没有的事实/例子/结论(加料 = 幻觉);(b) 确切细节一字不改——命令/报错原文/数字/版本/路径/代码片段是锚点不是表达;(c) 结论不漂移——不改判断的方向与强度;(d) 推测不许写成确定——原对话是推测的,重写后仍标 `[待验证]`,不因讲解体读着确定就偷偷升格。总纲:**换讲法,不换事实**。（追问链呈现下"答"的处理已被 [0013](0013-transcript-verbatim-extract.md) 精化:改为从会话 transcript 逐字扣、不再重写;本条在主题网/解法卡等综合呈现下仍成立。）
   - **③ 操作与工具执行:默认噪音,唯结果构成认知锚点时结果升信号。** 让 agent 跑命令/改文件的**过程**是噪音;跑出来的**结果**若是笔记外找不回的锚点(报错原文、实测数字、跑了才发现的事实),结果升信号。留结果不留过程,留观测不留操作。
5. **分类降为"呈现侧重"**:消化之后,按"未来复用什么"决定呈现——复用**追问路径本身** → 保留问答链;复用**一条解法** → 提炼解法卡、问答过程压成一行;复用**一个要长期养的主题** → 织进主题网。不再是入口处的强制三选一;交叉场景以主线为骨、双链缝合。
6. **抽取职责上收**:既然"记什么/丢什么"统一由第 4 条的引擎处理,呈现骨架从"又管抽取又管排版"**瘦身成只管排版**,三模板"该记/该丢"的重复自然消除。
7. **老资产安置**:mode-a-dialogue 的"问题保真回答重写"与逐轮结构**升到基底层**;mode-a-research / mode-a-practice **降为呈现侧重说明**(大概率合并为一个 reference);source-fidelity 从 research 内**拆出**,变成"问答里引用了外部材料时的横切保真纪律";mastery-lens 挂到"主题网"呈现侧重下;anti-patterns 基本保留——它本就是信号/噪音分离的坏例库(第 7 条"搬运已留痕记录"正是噪音的一种)。
8. **质量自检两维随架构挂靠**:"信号/噪音"维从事后自检的一条变成对主引擎的**复核**(查漏网/误删,双保险);"研究型掌握测试"从挂在"研究型"改挂到"主题网呈现侧重"下。
9. **版本:直接吸收进 v1.0.0 候选**。旧的三选一入口**从未对外发布**(无 tag `ob-notes/v1.0.0`,候选在分支 `codex/ob-notes-obsidian-only`),故这次重构**不是 breaking**,发布出去的 v1.0.0 就是这个更成熟的架构。

## 证据(附来源,区分已证实/推断)

1. **已证实(库内)**:三模板专属取舍差异真实——mode-a-research.md:147 明写掌握视角"一次性的实战笔记不必套用,否则是过度设计";SKILL.md:52 交叉场景用"选一个主笔记类型 + 双链回指"打补丁,证三类非 MECE。
2. **已证实(库内)**:mastery-lens 自警"四问绝不能变成笔记里的固定章节...会让人为填空而填空、写出表演式的伪掌握"(mode-a-research.md:144-145)——证固定模板有诱导填空副作用。
3. **已证实(库内)**:三个 mode-a-*.md 的 `depends_on` 高度重叠,"该记什么/该丢什么"三份清单大量重复——SSOT 维护压力。
4. **已证实(库内)**:dialogue 已含"问题保真、回答重写"雏形(mode-a-dialogue.md:13、105 的"回答用讲解体、禁止转写体"),本决策将其从 dialogue 专属**升为基底通则**。
5. **已证实(库内)**:dev-log 决策表记录用户否决 OKC 8 分类的理由正是"类别越多 = 判断负担越大 = 误分类越多"——本决策消除入口分类,与该判断同向。
6. **推断**:"有问 = 有消化"作为沉淀判据——用户经验判断,合理但待 dogfood 检验误判率。
7. **推断**:信号/噪音分离作为主引擎比"分类"更贴知识本质;但判据"删了理解会不会受损"是主观的,弱 agent 可能判不准,靠 anti-patterns 坏例库兜底——待评测证实。

## 存疑 / 待验证

- **整套架构未经 dogfood 实测,试行待验证**;发布前须补 F/G② 评测,重点验:交叉场景误分类率、信号/噪音判据的误删率、重写四镣铐是否真能挡住幻觉与结论漂移。
- **三限定参照读者的松紧**:第三限定"懂通用常识"的边界在真实笔记上会不会又诱发"这算不算常识"的争议,待实测。
- **research/practice 的终态**:是"合并成一个呈现侧重 reference"还是"各留薄壳",实施时按 depmap 影响面定。
- **无问存档划出后的需求反弹**:用户实际是否会有"就想让 ob-notes 顺手存一下"的诉求,观察;若反弹再议(a)/(b)。
