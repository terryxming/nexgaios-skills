# 0015. 以证据约束的忠实提炼取代全文逐字

- 状态:已接受
- 日期:2026-08-03
- 决策人:terry + Codex
- 取代:0014


## 背景

0014 为避免模型二次生成导致信息漂移，要求三种呈现的正文一律从 transcript 逐字扣。这个方案保护了字面信息，却把「避免漂移」和「全文逐字」绑定在一起：解法卡难以扫读，主题网难以跨轮次整合，skill 的知识提炼能力被压缩成 transcript 编排。

用户重新提出核心问题：逐字保真是否真是本 skill 的最高优先级；若允许模型重新组织，又如何控制结果漂移。双方确认，核心能力应是**可追溯的忠实提炼**，逐字只是其中一种保真级别。


## 决策

1. 把通用目标从「正文一律逐字」改为「重要结论可追溯、关键语义不漂移」。
2. 在成文前建立内部证据账本，为候选结论登记来源轮次、来源时间、事件时间、可信度、保真级别与受保护原子。账本不写进用户知识库。
3. 保留两档保真：用户明确要求问答实录、不要压缩或原样保留时，问与答逐字；解法卡和主题网默认允许忠实提炼。
4. 把用户决定与约束、命令、代码、配置、报错、数字、日期、版本、路径、字段 / API / 参数名，以及否定、条件、前提、例外和适用边界列为受保护原子，成文时必须与来源一致。
5. 给每条重要结论加来源脚注。脚注必须包含来源时间、对话轮次与足以支撑结论的证据片段；没有来源时间就写「时间未记录」，不得用笔记生成时间替代。事实另有明确发生时间时，在正文保留事件时间，两类时间不得混淆。
6. 写盘前逐条检查：结论有源、没有无源新增、确定性不升级、否定 / 条件 / 边界不丢、受保护原子一致、核心问题与决定仍在、可信度匹配证据。显式逐字模式另查问答是否真来自 transcript。
7. 保留 0013 的 transcript 提取机制，但将其作用域收回显式逐字模式。0014 的三种呈现全文逐字要求停止生效。


## 证据

- **用户问题**：本任务对话中，用户指出全文逐字可能不适合知识整理，但担心重新交给模型会产生漂移，并要求先确定 skill 的核心能力与实现方法。来源：本任务对话，2026-08-03，原记录未提供时分。
- **用户确认**：用户确认按「证据约束的忠实提炼」方向优化，重要结论使用来源脚注，并追加来源时间要求。来源：本任务对话，2026-08-03，原记录未提供时分。
- **本地源码检查**：0014 当前把追问链、解法卡、主题网都约束为逐字正文；`presentation.md` 的主题网只能编排逐字块，无法正常综合。来源：本仓 `skills/first-party/ob-notes/SKILL.md`、`references/distill.md`、`references/presentation.md`，检查于 2026-08-03。
- **运行边界检查**：现有 `extract_transcript.py` 在当前 Codex 环境无法凭 `CLAUDE_CODE_SESSION_ID` 定位会话，因此逐字能力本身也依赖平台与可用来源。来源：本地运行结果，2026-08-03。


## 影响

- `distill.md` 新增 `evidence-chain`，成为内部证据账本、受保护原子与保真级别的唯一家。
- 追问链继续逐字；解法卡与主题网恢复模型的组织、合并与讲解能力，但受证据链约束。
- 笔记的重要结论新增带来源时间的脚注；frontmatter schema 与 tag 体系不变。
- `quality-check.md` 从检查「有没有偷偷重写」改为检查事实、强度、边界与来源是否漂移。
- 对外版本仍为尚未发布的 `2.0.0` 候选，不另起版本。


## 存疑 / 待验证

- 证据账本与漂移检查目前仍是 agent 执行的语义纪律，真实稳定性需经用户确认后的行为评测与 dogfood 验证。
- 外部长文的 `source-fidelity` 不在本决策范围内，继续沿用现有覆盖机制，待单独拍板。
- Codex transcript 定位、compaction 跨文件回溯、`parentUuid` 分支重建与图片附件不在本次范围内。
