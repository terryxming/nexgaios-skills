# 0014. 三种呈现正文一律逐字，区分「重写」与「编排」（扩展 0013 作用域）

- 状态:已接受（设计已定，用户拍板；`[试行待验证]`——未 dogfood、evals 待用户过目后跑）
- 日期:2026-07-07
- 决策人:terry(公司机) + Claude


## 背景

0013 把"从会话 transcript 逐字扣"**限定在追问链**呈现，并明确保留"主题网 / 解法卡的答仍走 0011 的回答重写（四镣铐约束）"。即当时是**分流**:追问链逐字，综合呈现重写。

用户本轮提出更强的统一原则:**所有信息沉淀禁止重写，正文一律从 jsonl 逐字摘取**。理由与 0013 同源、但推到底——把内容交给 LLM 重写是**又一次概率性生成**:同一段重写两次都不一样、都对不上当时真正说的;长会话 compaction 后 agent 记忆已是压缩版，连逐字原料都没有。0013 已用这套论证拔掉追问链的重写病根，却把同样的病根留在了主题网 / 解法卡。

关键观察:用户自己描述的笔记骨架**已隐含答案**——「① 30 秒读法（用几句话概括）+ ② 正文（完整保真、不压缩不重写）」。① 本就是综合概括，② 才要求逐字。所以真正要定的只有一处:**"正文逐字"要不要也覆盖主题网 / 解法卡**。经分析（主题网天生是跨会话综合，纯逐字会退化或掐死其价值），用户拍板选"综合头 + 逐字正文"路线，并明确"主题网跨会话每次追加逐字块、作者只写小标题 / 双链编排、不改块内文字"。


## 决策

1. **transcript-extract 从追问链专属升为三种呈现正文的通用产出法。** 追问链 / 解法卡 / 主题网的正文都从会话 transcript 逐字扣;0011 决策 4·② 的"回答重写"路径**整体删除**（不再有任何呈现走重写）。
2. **区分「重写」与「编排」，划定唯一红线。**
   - **重写（禁）**:重新生成内容的文字——换措辞复述、把对话重讲、替 agent 补说明。凡让 LLM 再产一次内容的都是重写。
   - **编排（留）**:不碰逐字块内部一个字，只在块之外组织——挑块、排序、加小标题、写导航句（每轮总纲）、建双链。
   - 一句总纲:**块内逐字，块间自由。** 导航句须与逐字块视觉分离、不得复述或替换块内文字。
3. **30 秒读法综合头是唯一允许综合概括处，三种统一。** 加"背景（为什么产生本篇）"字段;套用到解法卡（原仅一句话）;字段定为 是什么 / 背景 / 解决什么 / 最重要结论（1–3 条带可信度）/ 怎么用 / 前置（主题网另加 边界）。
4. **主题网正文改为逐字块编排。** 由内容结构（小标题）+ 双链组织逐字块，不套固定骨架也不再"放手写讲解";跨会话深挖=追加新逐字块。`mastery-lens` 从"用行文写出掌握"转为"用挑块 / 编排体现掌握"——答不出四问的，标待深挖钩子、不臆造补写。
5. **source-fidelity(外部长文) 在逐字架构下的处理待定。** 覆盖表并入综合头、正文放逐字讨论？还是另设机制？本次标 `[待定 2026-07-07]`、保留原设计不动，待用户拍板后单独重构。
6. **版本 major bump 1.0.0 → 2.0.0（breaking:模板结构变更）;evals 同步翻**（改契约必改用例，ADR-0012）。


## 与 0013 的关系

**本决策扩展 0013 的作用域，不取代其机制。** 0013 的 transcript-extract 逐字扣脚本、结构层 / 语义层滤除规则、图片保留、跨文件回溯全部照旧沿用;变的只是**作用域从"仅追问链"扩到"三种呈现"**。因此:

- 0013 保留有效——它是逐字扣的机制定义。
- 0013 里"主题网 / 解法卡仍走回答重写""二者不整段逐字扣"等**作用域限定语句作废**，以本决策为准。


## 证据(附来源，区分已证实/推断)

**已证实:**

1. **用户明确决策**:本仓对话（2026-07-07）AskUserQuestion,用户在"综合头 + 逐字正文（推荐）/ 彻底逐字零编排 / 保留现状分流"三选一中选**综合头 + 逐字正文**,并批注"主题网跨会话每次追加逐字块、作者只写小标题 / 双链编排、不改块内文字"。
2. **核心论证已在 0013 证实并沿用**:「答重写=又一次 LLM 概率生成、与原话对不上」「compaction 令 agent 记忆失真、唯一 ground truth 是 jsonl」——0013 证据段已立,本决策只是把同一论证从追问链推广到三种呈现,不引入新的未验事实。
3. **官方最佳实践核对**（platform.claude.com best-practices 全文,2026-07-07 重取成功,`[已证实]`）:doc 明确——SKILL.md 宜精简 <500 行、渐进披露且引用一级深、**description 用第三人称（正文示例通篇祈使句，无"正文须第三人称"之说）**、eval 驱动（先建评测）、feedback loop（validate→fix→repeat）、output 用 template pattern。本次落地与之一致:SKILL.md ~110 行、补的三节均指针式短节、评测规则下沉 evals/README、正文保持祈使、description 已是第三人称、quality-check 即 feedback loop。

**推断(待验证):**

4. **主题网"逐字块编排"能承载跨会话深挖**——设计上成立（逐字块可追加、可双链），但正向效果 n=0、未 dogfood,标 `[试行待验证]`。
5. **解法卡纯逐字块仍足够扫读**——报错 / 命令本就逐字,根因 / 解法用原话块理论可行,但是否比旧的清爽重写更好用未验。
