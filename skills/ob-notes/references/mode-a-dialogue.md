# Mode A · 问答实录型笔记

适用于"连续追问本身有复用价值"的沉淀：用户一路追问、纠错、要求解释底层原因，理解路径比单个结论更重要。本质是**一篇可重走认知路径的学习 / 复盘实录**，不是压缩后的主题论文，也不是一次性解法卡。

格式细节一律遵循 `frontmatter-tags.md`，本文件只规定问答实录型特有的结构与取舍。

## 何时用问答实录型（vs 研究型 / 实战型）

- **问答实录型**：用户明确说"不要压缩 / 问答实录 / 保留我的问题 / 逐字留痕"，或连续追问把一个问题从表层逼到底层，过程本身有复用价值。→ 保留提问链与关键回答。
- **研究型**：目标是整理成一个长期生长的主题知识库。→ 走 `mode-a-research.md`。
- **实战型**：目标是以后照着解决同类问题，过程不重要。→ 走 `mode-a-practice.md`。

判据：未来的我最想复用的是**结论结构**，还是**当时怎么一步步问出来的**？若后者更重要，走问答实录型。

## 该记什么

- 用户每一轮关键提问，尽量原样保留，用 `> [!question] 我的提问` 标出。
- agent 的关键回答、被用户指出的问题、修正后的底层解释。
- 对话里出现的确切命令、路径、提交、报错、数字、版本、文件名。
- 认知转折：表层解释为什么不够、下一轮追问逼出了什么。
- 可信度约定：哪些是实测事实，哪些是复盘推断，哪些是待验证方案。
- 可复用动作：下次遇到同类情况如何检查、如何追问、如何避免复发。

## 该丢什么

- 寒暄、重复确认、无信息量的过渡语。
- 纯工具日志，除非它支撑结论。
- 与追问链无关的旁支。

注意：**问答实录不是完整聊天粘贴**。它要保留追问链和证据细节，但仍要编辑出主线。

## 写作纪律

- **用户问题优先保真**：用户的关键提问不要改写成摘要；如果问题很长，可保留原句并在回答前补一句"这问在追什么"。
- **轮次标题服务阅读**：用 `〔第一轮提问：...〕` 这类标题标出追问层次，不把每一轮都压成同权重流水账。
- **保留纠错瞬间**：用户指出"这不是真正原因"、"格式明显不一样"这类反馈，是认知转折，必须保留。
- **不要把问答改成 FAQ**：FAQ 会打散原始追问顺序；问答实录的价值在于保留理解如何推进。
- **结论仍要可复用**：末尾必须有小结 / 下次怎么用 / 生长钩子之一，避免只剩聊天记录。

## 与其它类型的边界

- 问答里沉淀出一个稳定主题，后续还会继续深挖：可另起研究型笔记，并在问答实录里双链过去。
- 问答里只剩一个明确操作解法：优先实战型，不必保留完整提问链。
- 用户明确说"不要压缩"时，默认问答实录型；除非用户同时要求整理成研究综述或解法卡。
