# 认知地图 + 学习阶梯 — 让骨架从主题自身长出来

这是整个 skill 的**地基与引擎**。用户面对一个新知识点，最大的障碍不是没有资料，而是**看不到立体骨架、不知道从哪下脚**——只看得到零散的局部、某个孤立的点，点是悬空的，学得零碎、效率极低。

这一步不急着开讲，先为主题**长出一张认知地图 + 一架学习阶梯**，让每个知识点都挂在骨架上、有位置、有来龙去脉。做到**从整体能拆到原子，从原子能逆推整体**。

---

## 两样东西，别混

- **认知地图（结构 / 全景）**：主题由哪些部分组成、彼此是什么关系（因果、依赖、层次、对立）。回答"这个主题的立体骨架长什么样、每个点在哪"。
- **学习阶梯（路径 / 顺序）**：从哪开始、先学什么后学什么、由浅入深的台阶。回答"我从哪下脚、怎么一步步爬"。

地图是**地形图**（有什么、在哪），阶梯是**路线图**（怎么走）。地图解决"看得到立体骨架"，阶梯解决"知道从哪开始"。

---

## 铁律一 · 自生长，绝不套框架

认知地图的结构**必须从这个主题自身的逻辑推出来**，绝不套一个"架构 / 原理 / 数据流 / 事件流 / 设计模式……"之类的**预设维度清单**往里填。预设格子会**削足适履**：把主题真实的结构打碎、塞进不合身的格子，还诱导每格均匀填浅。

**怎么让骨架自生长：**

1. 先抓这个主题的**核心问题 / 第一性矛盾**——它为解决什么根本问题而存在。
2. 顺着它的**因果 / 依赖 / 层次链条**展开：A 决定 B、B 逼出 C……让骨架顺着主题内在逻辑生长，而不是并列罗列一堆维度。
3. 结构由主题决定，**一主题一个样**：一个主题的骨架是"一条因果链"，另一个可能是"几根并列支柱"，再一个是"一棵分层树"或"一张对立关系网"。不预设形状。

> **范本（学 agent）**：骨架不是"13 个平铺维度"，而是一条**因果链**——
> `LLM 是无状态的文字接龙引擎 → 正因它无记忆、只会吐字 → 必须有 harness 套壳、喂上下文、接工具，它才像个会做事的 agent`。
> 这条链是从"LLM 无状态"这个事实**必然推出**的，不是往格子里填出来的。骨架自己长成了这个样子，因为主题的逻辑就长这样。

---

## 铁律二 · 整体 ↔ 原子，双向可导航

一张好的认知地图必须能**双向走**——这是把零散知识变立体的关键：

- **从整体拆到原子**：地图**分层**，顶层是主干，能逐层钻取到最小的、不可再分的知识点。
  （agent：四柱总链 → Harness → 上下文组装 → hooks → 31 个事件 → `exit 2` 的拦截语义。）
- **从原子逆推整体**：拿到任意一个孤立的点，能沿骨架**逆向定位**——它属于哪根主干、为什么存在、连回全局。
  （拿到"pre-flight hook 那行字"，能逆推回"harness 在组装阶段注入上下文"这一层、连回四柱全局。）

**每个点都在骨架上有坐标，不悬空。** 学的时候知道"我现在在整体的哪个位置"；遇到一个新点，知道"它该挂在哪、由什么推出、能再拆成什么"。这正是零散学习效率低、而立体骨架效率高的分界。

**落到图上**：产出认知地图时，为每个知识点显式标注它的**上位**（属于哪个父节点 / 主干）与**下位**（能再拆成哪些子点），让双向导航能力落在图的结构里，而不是嘴上说说。

---

## 学习阶梯 · 从地图排出下脚顺序

认知地图给了"有什么、在哪"，学习阶梯再给"从哪开始、怎么爬"：

- 按**依赖顺序**排台阶：前置的先学（学 harness 之前先懂"无状态"，否则 harness 为什么存在都说不清）。
- **由浅入深分级**：每级是一个能站稳的台阶，标出"这一级掌握什么、到什么程度算过关、可以上下一级"。过关标准要**可自测**，不用"熟悉 / 了解"这类没法验的词。
- **给用户定位**：主动问一句"你现在大概在第几级 / 对哪块已经懂了"，把阶梯锚到用户的真实起点——**阶梯的价值一半在定位**。

---

## 产出物

一张**让用户看到立体骨架（认知地图）+ 知道从哪下脚（学习阶梯）**的图，且整体↔原子双向可导航。这是后续所有学习的**导航底图**。

要长期留存 → 交 **ob-notes**：这种"要反复回来深挖、逐步充实"的主题骨架，天然对应 ob-notes 的主题网。本 skill 不自己写盘。

---

## 审查关 · 生成后一律必审（地基质量闸）

认知地图 + 学习阶梯是**一次性生成的**，模型凭记忆产出必有遗漏、混淆、过时错误（权重训练完就冻结、之后的信息它不知道，且模型本是概率预测）。后续所有学习都建在这张地图上——**地基错了后面全歪**。所以地图生成后**一律必审**（当前策略，使用一段后再评估是否放宽）。

**委派一个独立的专职审查子 agent**，不由生成者自审（生成者有确认偏误，独立对抗视角才挑得出错）：

- **先查证，再表述**：联网查官方文档（一手）、本地工具实跑实证，凡能核实的必核实，不凭模型记忆断言。查不到就诚实标「待验证」，绝不编造条目 / 数字 / 名称 / URL。
- **审四件事**：① 完整性——有无遗漏关键节点；② 正确性——哪些对、哪些错（错的给官方正确说法 + 出处）；③ 清晰性——哪些混淆、边界模糊、易误导；④ 结构——是否真从主题逻辑自生长、是否整体↔原子双向可导航。
- **每条关键断言标可信度五级**：**一手权威**（官方现抓核对）/ **第三方转译**（非官方来源）/ **已验证**（实跑实测过）/ **推断**（推理判断，附依据）/ **待验证**（没核到，存疑）。
- **产出审查报告** → 据此修正地图（补遗漏、改错误、拆混淆、重排结构），可信度落到节点上；修正后再进方法二。

> 尤其警惕**时效性错误**（易漂移量）：具体数字、版本、事件 / 配置项名称最容易过时——凡此类宁可写"随版本增长，以官方页为准"，也不写死一个会过期的数字。

## 配图（帮一眼看到立体骨架）

认知地图宜**配一张图**——loop 环、骨架树、或"缺陷 → 补偿支"的分支图，让用户一眼看到立体结构（认知地图的价值一半在"看得见全貌"）。图与文字骨架保持一致；图里的具体数字 / 名称同样受审查关约束，过时即误导。

---

## 建图之后

**审查通过、地图修正后**，进入方法二——在骨架上圈出最重要的 20%（见 `focus-and-plan.md`）。别停在"图画得很漂亮但没真学"：地图是为学透服务的底图，不是终点。
