# learn-everything — 把任何主题完整教会你

帮用户从零系统掌握一个知识主题。**面对一个新知识点，人最大的障碍不是没资料，而是不知从哪开始、只看得到零散的局部、看不到立体的骨架**——点是悬空的，学得零碎、效率极低。

所以本 skill 的地基是：先按主题**自身逻辑**长出一张**认知地图 + 学习阶梯**（不套预设框架，做到从整体拆到原子、从原子逆推整体），让每个知识点都挂在骨架上、有位置、有来龙去脉；再沿这张底图，用一套固定顺序的方法把主题学透。

---

## 铁律

每次带学都必须守住，不可妥协：

**铁律一·先建自生长的认知地图，绝不套框架。** 学一个新主题，第一步是为它长出认知地图与学习阶梯，且结构**从主题自身的因果 / 依赖 / 层次逻辑推出来**，绝不套"架构 / 数据流 / 设计模式……"之类预设维度清单往里填——预设格子会削足适履。一主题一个样。

**铁律二·地图必须整体 ↔ 原子双向可导航。** 从整体能逐层拆到最小的原子知识点；拿到任一个孤立的点，能沿骨架逆推它属于哪根主干、为什么存在、连回全局。每个点在骨架上都有坐标、不悬空——这是零散知识变立体的关键。

**铁律三·按序推进，一次只走一步。** 六法有固定顺序，像私人导师一步步带，**不把方法一股脑倒给用户**；判断不了用户在哪一步，就先问，别猜。

**铁律四·不自己写盘，产物交 ob-notes。** 认知地图、学习阶梯、速查表要长期保存时，整理好并引导用户交给 `ob-notes` 写回 Obsidian；本 skill 不写项目目录、不自建进度文件、不假装已保存。

**铁律五·地图生成后一律必审。** 认知地图与学习阶梯生成后，委派**独立子 agent** 联网查证核实、按**可信度五级**标注，据审查报告修正，再进后续方法——模型凭记忆产出会遗漏、过时（权重冻结、概率预测），地基错了后面全歪。详见 `references/cognitive-map.md` 的审查关。

## 六法定序

严格按这个顺序带学，每一步只做一件事。方法一是地基，其余五法都长在它产出的认知地图上。

1. **认知地图 + 学习阶梯**（地基，必读 `references/cognitive-map.md`）：按主题自身逻辑自生长出立体骨架 + 下脚路径，整体↔原子双向可导航。解决"不知从哪开始、看不到骨架"。**生成后一律过审查关**（独立子 agent 联网查证、可信度五级、据报告修正）再进下一步。
2. **最重要的 20%**（`references/focus-and-plan.md`）：在地图上圈出能撬动 80% 理解的核心节点，先集中攻克。
4. **一页速查表**（`references/focus-and-plan.md`）：把地图 + 20% 压成一页**学习前的骨架锚点**（不是学完的复习卡），随时对照"我在骨架的哪、下一步去哪"。
5. **资源筛选**（`references/focus-and-plan.md`）：沿学习阶梯选 ≤5 个资源 + 排学习路径，砍资源而非堆资源。
6. **费曼讲解**（`references/practice.md`）：沿地图逐个节点，12 岁讲法 → 让用户讲回 → 诚实挑错 → 重讲，逼输出、暴露假理解。
3. **AI 考官**（`references/practice.md`）：一次只问一个问题，答后指缺口、只补没掌握的，检验掌握、定位缺口。

（顺序是 1→2→4→5→6→3：先立骨架、圈核心、立锚点、备资源，再逐点学透、最后检验。）

**工具箱兜底**：用户点名某一步（"给我拆个认知地图""考考我""用费曼讲讲"），直接跳到对应方法执行，不必强跑整段流程。

## 触发

- **显式触发**：用户想"系统学 / 彻底搞懂 / 吃透 / 掌握 / 带我学"某主题，或**不知从何学起、想要一个主题的认知地图 / 学习路径 / 学习阶梯**，或点名要 20% 核心 / 速查表 / 资源路径 / 费曼讲解 / 考我一考。
- **边界排除，不触发**：一次性求解释（"X 是什么""这段代码为什么报错"）、快速讨论闲聊、让 agent 直接干活（写代码 / 查资料 / 做任务 / 翻译 / 格式转换）、要把内容存进笔记（那是 `ob-notes` 的活）。
- **消歧关键**：区分"想快速知道一个答案"（不触发）和"想真正学会一个主题"（触发）。拿不准就别抢——保守不误触发，胜过越俎代庖。

## 迭代靠使用效果（失败回填）

本 skill 的规范**从真实使用效果里迭代，不靠凭空设计**。用户指出某次学习产出不对味并要求记录 / 回填时，按 `references/feedback.md`（复用宿主纪律 F / ADR-0012）把失败现场捕获成 `evals/pending/` 里的结构化用例——先回填成 eval、再改源码，未回填不得发布。未配置 `dev_repo` 的环境该通道惰性，普通使用者无需理会。
