# Mode A · 问答实录型笔记

适用于"连续追问本身有复用价值"的沉淀：用户一路追问、纠错、要求解释底层原因，理解路径比单个结论更重要。本质是**一篇可重走认知路径的教材**——不是对话存档，不是压缩后的主题论文，也不是一次性解法卡。

一条总纲贯穿全篇：**问题保真、回答重写。** 用户的提问是史料，原样保留——它记录了理解如何被一步步推进；回答是教材，必须面向未来读者重新讲一遍——当时的对话原文只是素材。两侧待遇不对称，正是问答实录与"聊天记录"的分界。

格式细节一律遵循 `frontmatter-tags.md`，本文件只规定问答实录型特有的结构与取舍。

## 何时用问答实录型（vs 研究型 / 实战型）

- **问答实录型**：用户明确说"不要压缩 / 问答实录 / 保留我的问题 / 逐字留痕"，或连续追问把一个问题从表层逼到底层，过程本身有复用价值。→ 保留提问链，重写讲解。
- **研究型**：目标是整理成一个长期生长的主题知识库。→ 走 `mode-a-research.md`。
- **实战型**：目标是以后照着解决同类问题，过程不重要。→ 走 `mode-a-practice.md`。

判据：未来的我最想复用的是**结论结构**，还是**当时怎么一步步问出来的**？若后者更重要，走问答实录型。

## 该记什么

- 用户每一轮关键提问，原样保留，用 `> [!question] 我的提问` 标出。
- **认知增量——每一轮的主角**：进入这轮前的理解错/浅在哪，这轮之后被修正成了什么。"你的理解对一半，错的是这里"价值最高；用户指出"这不是真正原因""格式明显不一样"这类纠错反馈是认知转折，必须保留。
- 修正后的完整讲解：确切的命令、路径、报错原文、数字、版本、代码片段、对比表——**笔记之外找不回来的知识锚点**（铁律二）。
- 每轮末尾一句**可带走的总纲**：判断、公式或对比（如"非对称验身份、对称藏数据"）。
- 可信度约定：哪些是实测事实，哪些是复盘推断，哪些是待验证方案（按 credibility-spec）。

## 该丢什么

- 寒暄、重复确认、无信息量的过渡语。
- 当时回答的组织残渣：口语化铺垫、后来被修正的中间版本——修正的**结果**进讲解，被丢弃的中间版本只在"它错在哪"本身有教学价值时保留。
- **已在别处留痕的过程记录**（提交链、分支列表、文件清单、交接文档正文等）：只引用不搬运，见 `anti-patterns.md` 第 7 条。
- 纯工具日志，除非它支撑结论。
- 与追问链无关的旁支。

注意：**问答实录不是完整聊天粘贴**。保真的是问题与转折，正文主线要编辑出来。

## 写作纪律

- **问题保真**：用户的关键提问不要改写成摘要；问题很长可保留原句，并在回答前补一句"这问在追什么"。
- **回答用讲解体，禁止转写体**：回答区是写给未来读者的课，不是对当时对话的转述。凡出现"agent 当时解释说 / 随后承认 / 它的回答里有一个判断"这类叙事视角，就是在转写而非讲解——把修正后的理解直接讲出来。当时的原话只在**它本身是证据或认知转折**时引用（用户的纠错原话、暴露误解的关键错误陈述），引用之后仍要用讲解收束，不能让引用替讲解干活。
- **每轮收口一句总纲**：每轮末尾给一句可带走的判断/公式/对比；30 秒读法的"最重要结论"应能直接从各轮总纲中摘出。收不出总纲的轮次，说明该轮没有独立的认知增量——考虑并入相邻轮。
- **轮次标题服务阅读**：用 `〔第一轮提问：...〕` 这类标题标出追问层次，不把每一轮压成同权重流水账。
- **不要把问答改成 FAQ**：FAQ 会打散原始追问顺序；问答实录的价值在于保留理解如何推进。
- **结论仍要可复用**：末尾必须有小结 / 下次怎么用 / 生长钩子之一，避免只剩聊天记录。

## 与其它类型的边界

- 问答里沉淀出一个稳定主题，后续还会继续深挖：可另起研究型笔记，并在问答实录里双链过去。
- 问答里只剩一个明确操作解法：优先实战型，不必保留完整提问链。
- 用户明确说"不要压缩"时，默认问答实录型；除非用户同时要求整理成研究综述或解法卡。
