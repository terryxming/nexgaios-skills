# 信号/噪音分离 — 从问答里蒸馏出该沉淀的东西

分离信号与噪音是写任何笔记前的第一动作，也是本 skill 的核心引擎。一段人与 agent 的问答流里混着两种东西：值得进笔记的**信号**，和达成任务时顺带产生的**噪音**。先分对，再套骨架——分错了，骨架再漂亮也只是把噪音排版得好看。格式细节（可信度、日期等）遵循 `frontmatter-tags.md`，本文件只定义「抽什么、滤什么、怎么保真」。

## 为什么以问答为基底

以问答为基底，因为有长期复用价值的知识几乎都在一问一答里被逼出来——哪怕「研究一个概念」，也是用户带着困惑追问、agent 应答、再追问。**把用户的「问」当认知路径的坐标保留，不当过程噪音压缩**：它记录了困惑如何一步步被想通，丢掉问就丢掉了思考本身。

反过来，用「有没有问」判断消化与否：当用户啃一篇外部长文却毫无疑问、只想顺手存档时，说明未消化——这不归本 skill。

遇到这种「无问存档」，别硬邦邦拒绝，点明分工并给一次转化机会：

- 说清 ob-notes 沉淀的是消化后的知识，纯存档更适合剪藏 / 稍后读工具（如 Obsidian Web Clipper）；
- 再反问一句「要不要就这篇聊几句你的疑问或关注点？那我就能帮你沉淀成真正消化过的笔记」——把「无问」变成「有问」的入口，而不是把用户推开。

## ① 判据：一句话，一个参照读者

对每一段内容，只问一句：

> **删掉这条，一个「没有这场对话记忆、不熟这个主题、但懂通用常识」的人，理解会不会受损？**

- 受损 → **信号**，留。
- 不受损 → **噪音**，滤。

按参照读者的三条限定把握边界：

- **没有这场对话记忆** → 默认全留对话里独有的东西。笔记就是对抗遗忘：三个月后你对这主题的记忆 ≈ 这篇笔记，没记下的永远找不回。
- **不熟这个主题** → 留住定义、前置、机制、确切细节。**宁可把读者当小白，也别赌他懂**——赌错就是误删。
- **但懂通用常识** → 给个下界，不必记「什么是命令行、什么是变量」，挡住「记一堆常识」式的过度保留（见 `anti-patterns.md` 第 3 条）。

前两条防误删（信号边界偏宽），第三条防止走到另一头。

**典型信号**：用户的问、认知转折（「你理解错的是这里」）、结论、笔记之外找不回的确切细节（报错原文、命令、数字、版本、路径、代码片段）。

**典型噪音**：寒暄客套、夸奖赞美（「太强了」「完美」这类无信息表述）、重复确认、跑题旁支、让 agent 干活的操作指令、工具执行日志、被修正掉的中间版本（除非它本身是有教学价值的反例）。

## ② 正文一律逐字：区分「重写」与「编排」

信号抽出后，把三种呈现的正文都从会话 transcript 逐字扣（见下方 transcript-extract），不走重写。原因：把答交给 LLM 重写是**又一次概率性生成**——同一段重写两次都不一样、都对不上当时真正说的；长会话上下文被压缩后，agent 对早期问答的「记忆」已是压缩版，连逐字原料都没有。唯一的 ground truth 是会话 jsonl。用户的问同样原样保真。

但「逐字正文」不等于「不许组织」。分清两件事：

- **重写（禁）**：重新生成内容的文字——换措辞复述一段答、把对话重讲一遍、替 agent「补一句说明」。凡是让 LLM 再产一次内容的都算重写，都可能丢信息或掺幻觉。
- **编排（留）**：不碰逐字块内部一个字，只在块**之外**组织——挑哪些块进笔记、按什么顺序摆、加小标题分节、写导航句（如每轮总纲）、建双链。编排作用于「块与块之间」，不作用于「块内文字」。

一句总纲：**块内逐字，块间自由。** 只在 30 秒读法综合头一处允许综合概括（它是导航、明确标为摘要），正文每一块都必须是原话。

> [!warning] 导航句不得替代或复述逐字块
> 编排时可写小标题、每轮总纲、双链，但它们是**块之外的脚手架**，须与逐字块视觉分离（如总纲用 `> **本轮总纲**` 附在逐字答之后），不得改动、复述或替换块内文字。一旦「导航句」开始转述块里说了什么，就退回成了重写。确切细节（命令、报错原文、数字、版本、路径、代码片段）本就在逐字块里，天然一字不改。

## ③ 操作与工具执行：留结果不留过程

问答里常穿插「帮我跑一下 / 改个文件 / 看看日志」这类操作。默认把它们当**噪音**——它们是达成任务的手段，不是认知内容。唯一例外：

> 当操作的**结果**构成认知锚点（报错原文、实测数字、跑了才发现的事实）时，**把结果升为信号**，过程仍是噪音。

**留结果不留操作，留观测不留过程。** 一条日志除非支撑某个结论，否则不进笔记。这也呼应 `anti-patterns.md` 第 7 条：已在别处留痕的过程记录（提交链、分支列表、文件清单）只引用不搬运。

**但把试错的弯路当信号，不当操作噪音。**「试了 X 方案、失败、因为它不支持 Y」这种带根因的失败是**负向知识**（防未来重蹈覆辙），要留——归解法卡的「踩过的弯路」或主题网的边界。划界看有没有「为什么」：机械操作 / 工具日志（如「跑了 npm install」）＝噪音；「试了什么、为什么不行」＝信号。

**把操作旁白也当噪音滤掉。** agent「我去读一下 / 先执行第 X 步 / 这就帮你查」这类宣告要调工具的报幕句，和工具执行本身一样是过程、不是回答——逐字扣（`transcript-extract`）时与重写时一律滤掉。

## transcript-extract：所有正文从 transcript 逐字扣

按 ② 的通则，把三种呈现的正文都从会话 transcript（jsonl）逐字扣、不经 agent 转述。脚本 `scripts/extract_transcript.py` 是它的机械实现（本 skill 唯一「读会话记录」的能力，纯只读、不碰用户库）。

三种呈现共用同一套逐字扣，差别只在扣完后怎么**编排**：

- **追问链**：把问答按轮次直接铺开。
- **主题网 / 解法卡**：把逐字块按内容结构（主题小节 / 现象·根因·解法）摆好。

摆的是块，不改块内一个字。

**结构层——机械保留 / 滤除（脚本负责，无主观判断）：**

- **保留**：user 消息的真人 `text`/`image` ＋ assistant 消息的 `text`/`image`，一字不改（含代码块、表格、图片）。
- **滤除**：assistant 的 `thinking`、`tool_use`；user 里的 `tool_result`；`mode`/`queue-operation`/`last-prompt`/`system`/`attachment` 等元数据整行；`isCompactSummary` 摘要行；`[Request interrupted by user]` 等中断标记。（注入内容——system-reminder、CLAUDE.md、hook 输出——不落盘，天然不在。）

**语义层——判断留舍（agent 负责，脚本判不了）：**

- **只留有认知增量的问答对**：在结构滤完剩下的干净问答里，滤掉纯操作指令轮次（「pull 到本地」「看下待做」这类无认知增量的项目导航），判据沿用 ① 的参照读者。
- **一并滤掉操作旁白**（见 ③）：答里夹的「我去读一下 / 先执行第 X 步」这类报幕句是过程、不是回答。

**图片**：`extract_transcript.py` 在传入 `--attachments-dir` 时，把 `image` block 的 base64 解码存进该目录、正文用 `![[文件名]]` 引用；沉淀时把 `{kb_root}/00 - raw/attachments/` 作为 `--attachments-dir` 传入（落点由 agent 显式给，脚本不自行推断 kb_root）。区分 `attachment` 类型行（那是 deferred_tools / agent_listing 等系统事件，属噪音）。

**跨文件回溯**：当会话由上下文压缩续接（jsonl 开头即 `isCompactSummary`）时，前半段原文在前序文件，沿 `logicalParentUuid` 回溯扣全。`[试行待验证]`——回溯确切规则待实机核（见宿主仓 ADR-0013）。

**平台**：Claude Code 已验证可扣；Codex 侧 rollout 的 payload schema 与运行时定位待验，未通前该侧降级为 agent 转述（平台差异见 sidecar，不写进本文件）。

## source-fidelity：引用外部材料时的原文保真

> [!note] 待定（2026-07-07）
> 在「正文一律逐字」（②）架构下，外部长文的处理方式尚未定：覆盖表并入 30 秒读法综合头、正文放会话里对它的逐字讨论？还是另设机制？本节暂 `[待定]`、保留原设计不动——遇到外部长文仍按下方旧法产出，待用户拍板后重构。

当信号里含一篇外部材料（文章、博客、白皮书、长报告、视频）、且用户对它有消化（有问、有讨论）时，最大的风险是**把长文压成一张观点卡**：只留「我的启发」，丢了原文的问题定义、分类、方法步骤、机制、例子、对比维度和限制条件——那样笔记既不能当知识、也不能当资料回查。用两道动作钉死它：

**① 在正文开头放来源元数据块**（比单个 source_url 更完整，给人直接可读的出处）：

```markdown
> [!info] 来源
> **原文链接**：
> **原文标题**：
> **作者**：
> **原文发布日期**：
> **笔记日期**：
```

字段能识别就如实填，识别不到写「不适用」，**不要猜**（猜出来的作者 / 日期是伪信息，违反 `credibility-spec`）。

**② 给一张原文结构覆盖表**：把默认保留类的章节枚举到最细层级（有 H3 就到 H3）；整节省略的（营销 / 履历）用 H2 一行带过。把 N 个子节折成一行 = 省略了 N-1 节——每行标「压缩 / 省略」的，**「原因」必须点名丢掉的具体内容**（如「未收 Mem0 六层模块名」）；写「拆成表」「理论压掉」**不算理由**。目的是把「有意取舍」和「无意丢失」分开。

```markdown
## 原文结构覆盖

| 原文部分 | 处理方式 | 原因 |
|---|---|---|
| {{问题定义 / 前言}} | 保留 | 是文章的问题定义，不能只留结论 |
| {{框架细节}} | 压缩 | 留比较维度，细节拆成要点 |
| {{作者履历}} | 省略 | 对本次复用价值低 |
```

判据：默认**保留**原文的问题定义、分类体系、方法步骤、机制怎么运作、关键例子、方案对比维度、限制 / 边界、可复用资料链接（含确切的模块名 / 工具名 / 参数）；默认**可压缩**营销介绍、作者履历、重复解释、与目标无关的细节。

**用实质闸放行，不用字数比率**：对每个被标「压缩」的技术 / 框架 / 方法，自问——**它的核心机制，能不能只凭这篇笔记读懂、不回原文？** 有一个读不懂 = 压过头，补回机制层。**覆盖表是记账手段，不是免压通行证**（落盘不足原文主干 1/4 时几乎必然有机制被压没，实质闸要逐项严过）。

**守源上限护栏**：只补原文**确实讲了**的；原文没展开的深层（算法 / 实现 / 协作流程）**不许编**，改写进「待验证」当待深挖钩子，日后另开研究从一手文档源码补。
