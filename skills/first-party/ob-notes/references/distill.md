# 信号/噪音分离 — 从问答里蒸馏出该沉淀的东西

分离信号与噪音是写任何笔记前的第一动作，也是本 skill 的核心引擎。一段人与 agent 的问答流里混着两种东西：值得进笔记的**信号**，和达成任务时顺带产生的**噪音**。先分对，再套骨架——分错了，骨架再漂亮也只是把噪音排版得好看。格式细节（可信度、日期等）遵循 `frontmatter-tags.md`，本文件只定义「抽什么、滤什么、怎么保真」。


## 为什么以问答为基底

以问答为基底，因为有长期复用价值的知识几乎都在一问一答里被逼出来——哪怕「研究一个概念」，也是用户带着困惑追问、agent 应答、再追问。把用户的「问」当**认知路径的坐标**保留，**不当过程噪音压缩**：它记录了困惑如何一步步被想通，丢掉问就丢掉了思考本身。

反过来，用「有没有问」判断消化与否：当用户啃一篇外部长文却毫无疑问、只想顺手存档时，说明未消化——这不归本 skill。

遇到这种「无问存档」，别硬邦邦拒绝，点明分工并给一次转化机会：

- 说清 ob-notes 沉淀的是消化后的知识，纯存档更适合剪藏 / 稍后读工具（如 Obsidian Web Clipper）；
- 再反问一句「要不要就这篇聊几句你的疑问或关注点？那我就能帮你沉淀成真正消化过的笔记」——把「无问」变成「有问」的入口，而不是把用户推开。


## ① 判据：一句话，一个参照读者

对每一段内容，只问一句：

> **删掉这条，一个「没有这场对话记忆、不熟这个主题、但懂通用常识」的人，理解会不会受损？**

- 受损 → **信号**，留。
- 不受损 → **噪音**，滤。

按参照读者的三条限定把握边界：

- **没有这场对话记忆** → 默认全留对话里独有的东西。笔记就是对抗遗忘：三个月后你对这主题的记忆 ≈ 这篇笔记，没记下的永远找不回。
- **不熟这个主题** → 留住定义、前置、机制、确切细节。宁可把读者当小白，也**别赌他懂**——赌错就是误删。
- **但懂通用常识** → 给个下界，不必记「什么是命令行、什么是变量」，挡住「记一堆常识」式的过度保留（见 `anti-patterns.md` 第 3 条「过度保留」）。

前两条防误删（信号边界偏宽），第三条防止走到另一头。

**典型信号**：用户的问、认知转折（「你理解错的是这里」）、结论、笔记之外找不回的确切细节（报错原文、命令、数字、版本、路径、代码片段）。

**典型噪音**：寒暄客套、夸奖赞美（「太强了」「完美」这类无信息表述）、重复确认、跑题旁支、让 agent 干活的操作指令、工具执行日志、被修正掉的中间版本（除非它本身是有教学价值的反例）。


## ② 建证据账本：先固定来源，再让模型组织

信号抽出后，先建立一份**内部证据账本**，再写笔记。账本不落入用户知识库；它的作用是把模型的生成空间限制在已核对的来源内，避免「把原信息重新喂给模型」时无锚漂移。

每条候选结论至少登记：

- **结论**：准备写入笔记的最小可判断陈述。
- **来源轮次**：哪一轮用户或 agent 的内容直接支撑它；多轮共同支撑就全部列出。
- **来源时间**：该段来源在对话中出现的时间。原记录只有日期就只写日期；没有时间就写「时间未记录」，不要用笔记生成时间补造。
- **事件时间**：决定、测试、观察或事实实际发生的时间；只有来源明确给出时才登记，没有就留空。
- **可信度**：按 `credibility-spec` 标已验证 / 待验证 / 推测。
- **保真级别**：标 `逐字` 或 `忠实提炼`。用户明确要问答实录、不要压缩、原样保留时选逐字；其余默认忠实提炼。
- **受保护原子**：必须和来源一致的字面信息，见下一节。

把来源脚注编号同时记到账本，成文时让每条重要结论带脚注。脚注格式与来源时间写法按 `frontmatter-tags.md` 的 `linking-convention` 执行。


## ③ 受保护原子：允许换讲法，不允许改事实

忠实提炼允许合并、排序、去重复和换一种更清楚的说法，但以下内容必须与来源一致：

- 用户已经确认的决定、约束和明确偏好。
- 命令、代码、配置、报错原文。
- 数字、日期、版本、路径。
- 字段名、API 名、参数名与其他标识符。
- 否定、条件、前提、例外、适用边界。
- 用户明确要求引用的原话。

这些内容是**受保护原子**。不要把「可能」写成「一定」，不要把「尚未验证」写成「已证实」，不要把「仅在 X 下成立」压成无条件结论，也不要省掉「不」「除非」「仅」「至少」等改变含义的词。

受保护原子之外的解释可以忠实提炼，但只能做来源支持的等义组织：不得新增事实、补造因果、替用户扩大决定范围，或把多轮里互相冲突的说法揉成一个看似确定的新结论。冲突仍在时并列记录，并按时间与可信度说明。


## ④ 按用途选择逐字或忠实提炼

- **追问链 / 问答实录**：当用户明确要保留追问路径、原样、不压缩时，使用逐字模式。问与答从 transcript 提取，只滤系统事件等不属于问答原文的结构噪音；操作旁白属于回答原文，完整逐字模式下也保留。
- **解法卡**：默认使用忠实提炼。按现象、根因、解法重组，受保护原子逐字保留，重要结论带来源脚注。
- **主题网**：默认使用忠实提炼。跨轮次或跨会话合并同一主题，保留条件、分歧与演化，重要结论带来源脚注。

逐字是特定输出模式，不是所有笔记的通用目标；通用目标是**可追溯的忠实提炼**。这样既保留模型的组织能力，也用证据账本、受保护原子与写盘前核对控制漂移。


## ⑤ 操作与工具执行：留结果不留过程

问答里常穿插「帮我跑一下 / 改个文件 / 看看日志」这类操作。默认把它们当**噪音**——它们是达成任务的手段，不是认知内容。唯一例外：

> 当操作的**结果**构成认知锚点（报错原文、实测数字、跑了才发现的事实）时，**把结果升为信号**，过程仍是噪音。

**留结果不留操作，留观测不留过程。** 一条日志除非支撑某个结论，否则不进笔记。这也呼应 `anti-patterns.md` 第 7 条「搬运已留痕的记录」：已在别处留痕的过程记录（提交链、分支列表、文件清单）只引用不搬运。

**但把试错的弯路当信号，不当操作噪音。**「试了 X 方案、失败、因为它不支持 Y」这种带根因的失败是**负向知识**（防未来重蹈覆辙），要留——归解法卡的「踩过的弯路」或主题网的边界。划界看有没有「为什么」：机械操作 / 工具日志（如「跑了 npm install」）＝噪音；「试了什么、为什么不行」＝信号。

**默认把操作旁白当噪音滤掉。** agent「我去读一下 / 先执行第 X 步 / 这就帮你查」这类宣告要调工具的报幕句，和工具执行本身一样通常只是过程——忠实提炼与普通问答整理时滤掉；但用户明确要求完整逐字、怎么问怎么答原样保留时，它属于回答原文，必须保留。


## transcript-extract：显式逐字模式从 transcript 扣原话

当用户明确要求问答实录、不要压缩或原样保留时，从会话 transcript（jsonl）逐字扣，不经 agent 转述。脚本 `scripts/extract_transcript.py` 是它的机械实现（本 skill 唯一「读会话记录」的能力，纯只读、不碰用户库）。解法卡与主题网不强制运行脚本，但仍须从可核对来源建立证据账本。

**结构层——机械保留 / 滤除（脚本负责，无主观判断）：**

- **保留**：user 消息的真人 `text`/`image` ＋ assistant 消息的 `text`/`image`，一字不改（含代码块、表格、图片）。
- **滤除**：
    - assistant 的 `thinking`、`tool_use`
    - user 里的 `tool_result`
    - `mode`/`queue-operation`/`last-prompt`/`system`/`attachment` 等元数据整行
    - `isCompactSummary` 摘要行
    - `[Request interrupted by user]` 等中断标记

    （注入内容——system-reminder、CLAUDE.md、hook 输出——不落盘，天然不在。）

**语义层——判断留舍（agent 负责，脚本判不了）：**

- **只留有认知增量的问答对**：在结构滤完剩下的干净问答里，滤掉纯操作指令轮次（「pull 到本地」「看下待做」这类无认知增量的项目导航），判据沿用 ① 的参照读者。
- **按用户要求处理操作旁白**（见 ⑤）：普通问答整理可滤掉答里夹的「我去读一下 / 先执行第 X 步」等报幕句；用户明确要求完整逐字、原样保留时不得滤掉。

**图片**：`extract_transcript.py` 在传入 `--attachments-dir` 时，把 `image` block 的 base64 解码存进该目录、正文用 `![[文件名]]` 引用；沉淀时把 `{kb_root}/00 - raw/attachments/` 作为 `--attachments-dir` 传入（落点由 agent 显式给，脚本不自行推断 kb_root）。区分 `attachment` 类型行（那是 `deferred_tools` / `agent_listing` 等系统事件，属噪音）。

**跨文件回溯**：当会话由上下文压缩续接（jsonl 开头即 `isCompactSummary`）时，前半段原文在前序文件，沿 `logicalParentUuid` 回溯扣全。`[试行待验证]`——回溯确切规则待实机核（见宿主仓 ADR-0013）。

**平台**：Claude Code 已验证可扣；Codex 侧 rollout 的 payload schema 与运行时定位待验，未通前该侧降级为 agent 转述（平台差异见 sidecar，不写进本文件）。


## source-fidelity：引用外部材料时的原文保真

> [!note] 待定（2026-07-07）
> 本轮只重构对话信息的证据链，没有重构外部长文的覆盖机制。本节继续按原设计执行，待用户另行拍板。

当信号里含一篇外部材料（文章、博客、白皮书、长报告、视频）、且用户对它有消化（有问、有讨论）时，最大的风险是**把长文压成一张观点卡**：只留「我的启发」，丢了原文的问题定义、分类、方法步骤、机制、例子、对比维度和限制条件——那样笔记既不能当知识、也不能当资料回查。用两道动作钉死它：

**① 在正文开头放来源元数据块**（比单个 source_url 更完整，给人直接可读的出处）：

```markdown
> [!info] 来源
> **原文链接**：
> **原文标题**：
> **作者**：
> **原文发布日期**：
> **笔记日期**：
```

字段能识别就如实填，识别不到写「不适用」，**不要猜**（猜出来的作者 / 日期是伪信息，违反 `credibility-spec`）。

**② 给一张原文结构覆盖表**：把默认保留类的章节枚举到最细层级（有 H3 就到 H3）；整节省略的（营销 / 履历）用 H2 一行带过。把 N 个子节折成一行 = 省略了 N-1 节——每行标「压缩 / 省略」的，**「原因」必须点名丢掉的具体内容**（如「未收 Mem0 六层模块名」）；写「拆成表」「理论压掉」**不算理由**。目的是把「有意取舍」和「无意丢失」分开。

```markdown
## 原文结构覆盖

| 原文部分 | 处理方式 | 原因 |
|---|---|---|
| {{问题定义 / 前言}} | 保留 | 是文章的问题定义，不能只留结论 |
| {{框架细节}} | 压缩 | 留比较维度，细节拆成要点 |
| {{作者履历}} | 省略 | 对本次复用价值低 |
```

判据：默认**保留**原文的问题定义、分类体系、方法步骤、机制怎么运作、关键例子、方案对比维度、限制 / 边界、可复用资料链接（含确切的模块名 / 工具名 / 参数）；默认**可压缩**营销介绍、作者履历、重复解释、与目标无关的细节。

**用实质闸放行，不用字数比率**：对每个被标「压缩」的技术 / 框架 / 方法，自问——它的核心机制，能不能**只凭这篇笔记读懂、不回原文**？有一个读不懂 = 压过头，补回机制层。覆盖表是记账手段，**不是免压通行证**（落盘不足原文主干 1/4 时几乎必然有机制被压没，实质闸要逐项严过）。

**守源上限护栏**：只补原文**确实讲了**的；原文没展开的深层（算法 / 实现 / 协作流程）**不许编**，改写进「待验证」当待深挖钩子，日后另开研究从一手文档源码补。
