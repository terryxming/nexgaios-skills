# 信号/噪音分离 — 从问答里蒸馏出该沉淀的东西

这是写任何笔记**之前的第一动作**，也是本 skill 的核心引擎。一段人与 agent 的问答流里，混着两种东西：值得进笔记的**信号**，和达成任务时顺带产生的**噪音**。分离做对了，后面套什么骨架都不跑偏；分离做错了，骨架再漂亮也只是把噪音排版得很好看。

格式细节（可信度标记、日期等）一律遵循 `frontmatter-tags.md`，本文件只定义“抽什么、滤什么、怎么保真”。

## 为什么以问答为基底

几乎所有有长期复用价值的知识，都是在一问一答里被逼出来的——哪怕“研究一个概念”，也是用户带着困惑追问、agent 应答、再追问的过程。**用户的“问”不是要压缩掉的过程噪音，而是认知路径的坐标**：它记录了困惑如何一步步被想通。丢掉问，就丢掉了思考本身。

反过来，**“有没有问”也是“消化与否”的判据**：啃一篇外部长文若毫无疑问、只是顺手存档，说明并未消化——那不归本 skill，交给剪藏/稍后读工具即可。本 skill 只蒸馏消化后的知识。

## ① 判据：一句话，一个参照读者

对话里每一段内容，只问一句：

> **删掉这条，一个「没有这场对话记忆、不熟这个主题、但懂通用常识」的人，理解会不会受损？**

- 受损 → **信号**，留。
- 不受损 → **噪音**，滤。

参照读者的三条限定，各有用处：

- **没有这场对话记忆** → 对话里独有的东西默认全留。笔记的作用就是对抗遗忘：三个月后你关于这主题的记忆 ≈ 这篇笔记，对话里没被记下的就永远找不回。
- **不熟这个主题** → 定义、前置、机制、确切细节都要留。**宁可把读者当小白，也别赌他懂**——赌错就是误删。
- **但懂通用常识** → 给个下界，不必记“什么是命令行、什么是变量”，挡住“记一堆常识”式的过度保留（见 `anti-patterns.md` 第 3 条）。

前两条保证**防误删**（信号边界偏宽），第三条防止走到另一头。

**典型信号**：用户的问、认知转折（“你理解错的是这里”）、结论、笔记之外找不回的确切细节（报错原文、命令、数字、版本、路径、代码片段）。

**典型噪音**：寒暄客套、重复确认、跑题旁支、让 agent 干活的操作指令、工具执行日志、被修正掉的中间版本（除非它本身是有教学价值的反例）。

## ② 问题保真，回答重写

信号内部，问和答的待遇**不对称**——这正是“问答实录”与“聊天记录粘贴”的分界：

- **问：原样保真，不许改写。** 用户的关键提问是史料、是认知坐标，连措辞一起保留（问很长可保留原句，并在回答前补一句“这问在追什么”）。
- **答：必须重写成给未来读者的讲解。** 当时对话里的回答只是素材，要面向“没有这场对话记忆”的读者重新讲一遍。

**重写锁死在叙述组织层，碰不到事实层。四条镣铐：**

1. **只重组，不新增** —— 只能重新组织对话里**已有**的信息，不许引入对话里没有的事实、例子、结论。加料 = 幻觉。
2. **确切细节一字不改** —— 命令、报错原文、数字、版本、路径、代码片段是**锚点不是表达**，原样保留，重写的自由不作用于它们。
3. **结论不漂移** —— 不改变原结论的方向与强度（把“可能”写成“一定”就是漂移）。
4. **推测不许写成确定** —— 原对话是推测的，重写后仍按 `credibility-spec` 标 `[待验证]`；不因讲解体读起来确定，就偷偷升格。

一句总纲：**换讲法，不换事实。** 自由度只在“怎么把叙述组织得让忘光的自己看懂”，越过事实红线就是编造。

> [!warning] 禁转写体
> 回答区是写给未来读者的课，不是对当时对话的转述。凡出现“agent 当时解释说 / 随后承认 / 它的回答里有个判断”这类叙事视角，就是在转写而非讲解。当时的原话只在**它本身是证据或认知转折**时才引用（用户的纠错原话、暴露误解的关键错误陈述），引用之后仍要用讲解收束，不能让引用替讲解干活。

## ③ 操作与工具执行：留结果不留过程

问答里常穿插“帮我跑一下 / 改个文件 / 看看日志”这类操作。默认它们是**噪音**——它们是达成任务的手段，不是认知内容。唯一例外：

> 操作的**结果**若构成认知锚点（报错原文、实测数字、跑了才发现的事实），**结果升为信号**，过程仍是噪音。

**留结果不留操作，留观测不留过程。** 一条日志除非支撑某个结论，否则不进笔记。这也呼应 `anti-patterns.md` 第 7 条：已在别处留痕的过程记录（提交链、分支列表、文件清单）只引用不搬运。

## source-fidelity：引用外部材料时的原文保真

当信号里含一篇外部材料（文章、博客、白皮书、长报告、视频）时——注意这只在用户**对材料有消化**（有问、有讨论）时才发生——最大的风险是**把长文压成一张观点卡**：只留“我的启发”，丢了原文的问题定义、分类、方法步骤、机制、例子、对比维度和限制条件。那样笔记既不能当知识、也不能当资料回查。两道动作钉死它：

**① 正文开头放来源元数据块**（比单个 source_url 更完整，给人直接可读的出处）：

```markdown
> [!info] 来源
> **原文链接**：
> **原文标题**：
> **作者**：
> **原文发布日期**：
> **笔记日期**：
```

字段能识别就如实填，识别不到写“不适用”，**不要猜**（猜出来的作者/日期是伪信息，违反 `credibility-spec`）。

**② 给一张原文结构覆盖表**：默认保留类的章节枚举到最细层级（有 H3 就到 H3）；整节省略的（营销/履历）可 H2 一行带过。把 N 个子节折成一行 = 省略了 N-1 节——每行标“压缩/省略”的，**“原因”必须点名丢掉的具体内容**（如“未收 Mem0 六层模块名”）；写“拆成表”“理论压掉”**不算理由**。目的是把“有意取舍”和“无意丢失”分开。

```markdown
## 原文结构覆盖

| 原文部分 | 处理方式 | 原因 |
|---|---|---|
| {{问题定义 / 前言}} | 保留 | 是文章的问题定义，不能只留结论 |
| {{框架细节}} | 压缩 | 留比较维度，细节拆成要点 |
| {{作者履历}} | 省略 | 对本次复用价值低 |
```

判据：默认**保留**原文的问题定义、分类体系、方法步骤、机制怎么运作、关键例子、方案对比维度、限制/边界、可复用资料链接（含确切的模块名/工具名/参数）；默认**可压缩**营销介绍、作者履历、重复解释、与目标无关的细节。

**放行用实质闸，不用字数比率**：逐个被标“压缩”的技术/框架/方法，自问——**它的核心机制，能不能只凭这篇笔记读懂、不回原文？** 有一个读不懂 = 压过头，补回机制层。**覆盖表是记账手段，不是免压通行证。**（落盘不足原文主干 1/4 时，几乎必然有机制被压没，实质闸要逐项严过。）

**源上限护栏**：只补原文**确实讲了**的；原文没展开的深层（算法/实现/协作流程）**不许编**，改写进“待验证”当待深挖钩子，日后另开研究从一手文档源码补。
