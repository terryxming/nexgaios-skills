# Changelog

本文件记录 ob-notes 对外版本间的变化（面向使用者），**只记"变了什么"**；为什么这么改、踩了什么坑、否决了什么备选，见 skill 内的 dev-log（面向维护者），此处不复述。

版本遵循语义化版本 `MAJOR.MINOR.PATCH`，规则见 `references/maintenance.md` 第 5 节。

## [2.0.0] - 2026-07-07

破坏性：正文一律逐字，三种呈现统一为「综合头 + 逐字正文」（宿主 ADR-0014，扩展 0013 作用域）。

- **答不再重写**——追问链 / 解法卡 / 主题网的正文都从会话 transcript 逐字扣，删除 1.0.0 里"主题网 / 解法卡重写成讲解"的路径。重写是又一次概率生成、会丢信息掺幻觉、对不上原话。
- 立「重写 vs 编排」界线：**块内逐字（禁改块内一字），块间自由（可挑块、排序、加小标题 / 总纲 / 双链）**。导航句不得替代或复述逐字块。
- 30 秒读法综合头三种统一、加「背景」字段（为什么产生本篇），并套用到解法卡（原仅一句话）；最重要结论放宽到 1–3 条。
- 主题网正文改为逐字块编排、跨会话追加逐字块；`mastery-lens` 从"写出掌握"转为"挑块 / 编排体现掌握"。
- `source-fidelity`（外部长文保真）在逐字架构下的处理**暂 `[待定]`**、保留原设计，待后续单独重构。
- SKILL.md 新增「输出格式」「失败边界」两节 + 脚本加载规则 + 评测规则指针（`evals/README.md`）。
- 评测同步翻转：`topic-web-still-rewrites`→`topic-web-verbatim-organized`（测逐字块编排而非重写）、解法卡用例补 30 秒读法与逐字断言。
- 维护文档 dev-log 按「单一事实源 + 索引 + 指针」拆分为 `dev-log/`（决策 / 时间线 / 踩坑三档）+ `dev-log.md` 索引。


## [1.0.0] - 2026-07-04

破坏性收敛 + 架构翻转：只做一件事——从人与 agent 的问答里分离出已消化的知识，写回 Obsidian。

- 移除项目目录 / dev-log 写入能力与 monitoring 回访机制；落点统一为 `{kb_root}/00 - raw/00 - inbox/`。
- 无问的顺手存档不再归本 skill（点明分工并引导，转交剪藏 / 稍后读工具）。
- 工作流从"判定类型套模板"翻转为"信号/噪音分离（新 `references/distill.md`）→ 按复用目标定呈现侧重（新 `references/presentation.md`）"。
- 问题保真；答按呈现分流——**追问链从会话 transcript 逐字扣（不重写）**、主题网 / 解法卡重写成讲解（换讲法不换事实）；操作与工具执行留结果不留过程（含操作旁白，试错弯路是信号）。
- 三种呈现侧重：追问链 / 解法卡（有骨架）、主题网（去骨架，只固定 frontmatter + 30 秒读法，正文结构服从内容）。
- source-fidelity（外部材料保真）从研究型专属改为横切纪律；mastery-lens（掌握视角）挂主题网下。
- tag 移除 `类型/项目日志`、新增 `类型/问答实录`；依赖声明立「规范性依赖 vs 指路引用」分界（maintenance §3）。
- 新增维护者失败回填通道（`references/feedback.md`，规则项 feedback-loop）：真实使用的失败案例一句话捕获成 `evals/pending/` 用例草稿，回填人在环，宿主 `lint --release` 未回填不得发布；config 可选键 `dev_repo` 门控，普通用户完全惰性。受控词表 26 项，依赖图重建。
- **追问链改为从会话 transcript 逐字扣**（新脚本 `scripts/extract_transcript.py` + 规则项 `transcript-extract`）：问答实录不再由 agent 事后重写，而是从 Claude Code 会话记录提取当时原话——逐字保真、只滤噪音（thinking / 工具调用 / 元数据 / 中断标记）与操作旁白；主题网 / 解法卡的答仍走重写。受控词表 26 → 27。
- 评测执行用例待随架构重写（触发边界不变）。
